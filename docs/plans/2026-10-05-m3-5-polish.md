## How the server and the web UI behave

These are the facts the tasks below match, cited at `d1597a583b`.

- **Archive and delete workspace.** The web UI archives first and deletes second: `PATCH /api/v2/chats/{chat}` with `{"archived": true}`, then `POST /api/v2/workspaces/{workspace}/builds` with `{"transition": "delete"}` ([`archiveChatAndDeleteWorkspace`](https://github.com/coder/coder/blob/d1597a583b/site/src/pages/AgentsPage/utils/agentWorkspaceUtils.ts#L105-L140), [`updateChat`](https://github.com/coder/coder/blob/d1597a583b/site/src/api/api.ts#L3349-L3354), [`deleteWorkspace`](https://github.com/coder/coder/blob/d1597a583b/site/src/api/api.ts#L1425-L1430)).
  The archive doubles as the eligibility check, since the server refuses it with 409 while any chat in the family runs, so a refused archive never deletes anything.
  A 404 or 410 from the delete means the workspace is already gone, and the archive stands ([`isWorkspaceNotFound`](https://github.com/coder/coder/blob/d1597a583b/site/src/pages/AgentsPage/utils/agentWorkspaceUtils.ts#L87-L90)).
  Any other delete failure leaves the chat archived, with no compensating unarchive, and the error points at the archived filter, where unarchiving is one click ([`notifyArchiveAndDeleteFailed`](https://github.com/coder/coder/blob/d1597a583b/site/src/pages/AgentsPage/utils/agentWorkspaceUtils.ts#L239-L276)).
  A delete build that matched no provisioner gets a warning that it runs once one comes online ([`notifyDeleteQueueState`](https://github.com/coder/coder/blob/d1597a583b/site/src/pages/AgentsPage/utils/agentWorkspaceUtils.ts#L224-L237)).
  The menu offers "Archive & delete workspace" only when the chat has a workspace ([`ChatActionsMenuItems`](https://github.com/coder/coder/blob/d1597a583b/site/src/pages/AgentsPage/components/ChatActionsMenuItems.tsx#L216-L237)).
  The web UI also looks the workspace up first: one the chat created or claimed is deleted without asking, and one that existed before the chat needs its name typed into a dialog ([`resolveArchiveAndDeleteAction`](https://github.com/coder/coder/blob/d1597a583b/site/src/pages/AgentsPage/utils/agentWorkspaceUtils.ts#L183-L222), [the dialog](https://github.com/coder/coder/blob/d1597a583b/site/src/pages/AgentsPage/AgentsPageLayout.tsx#L836-L847)).
- **MCP servers on create.** `POST /api/v2/chats` accepts `mcp_server_ids` ([`CreateChatRequest`](https://github.com/coder/coder/blob/d1597a583b/codersdk/chats.go#L653-L679)).
  The handler refuses an ID that is not an enabled server of the chat's organization with a 400, "One or more MCP server IDs are invalid or disabled." ([`postChats`](https://github.com/coder/coder/blob/d1597a583b/coderd/exp_chats.go#L1361-L1378), [`invalidChatMCPServerIDsResponse`](https://github.com/coder/coder/blob/d1597a583b/coderd/exp_chats.go#L1193-L1202)).
  The server adds every enabled `force_on` server to whatever the request selects ([`enforceForcedMCPServerIDs`](https://github.com/coder/coder/blob/d1597a583b/coderd/x/chatd/chatd.go#L1214-L1217)), so an omitted or empty list gives only the required servers.
  The web UI's new-chat form starts from every enabled server that is `force_on` or `default_on` ([`getDefaultMCPSelection`](https://github.com/coder/coder/blob/d1597a583b/site/src/pages/AgentsPage/utils/mcpSelection.ts#L3-L21)) and sends that selection with the create.

## Decisions this plan makes that the feedback left open

- **Where the tip is remembered.** In `state.toml` under `$XDG_STATE_HOME/scuttle/`, else `$HOME/.local/state/scuttle/`, the XDG home for state that is not configuration and is not worth backing up.
  The file is TOML, so a person can read it, and it is written through the same atomic 0600 writer as the config.
  Without either variable nothing can remember the tip, so it shows on each start.
- **What "once" means.** The tip shows on the blank chat scuttle starts on, in text mode only, and is recorded on the first draw that shows it.
  It stays on that welcome screen until a chat opens or is created, and then goes for the rest of the session, so `/new` later shows the welcome without it.
  Nerd mode never shows or records it, so switching a Nerd Font on and off again before ever seeing the tip still shows it once.
  `/help` keeps its Icons section in text mode, with the new words.
- **The spend reset.** The footer's spend field reads `spend $1.20/$50.00 (resets in 26d)`, with `time::until`'s text, whenever the server names the period's end, budget or not.
  At narrow widths the reset text goes before any whole field does.
- **`/mcp` on a blank chat.** The organization's MCP servers load with its model and workspace lists, tagged `Msg::ForOrg`, so a blank chat knows them without opening `/mcp`.
  A blank chat starts from the web UI's defaults (enabled `force_on` and `default_on` servers), `/mcp` shows that selection and toggles it with Enter, and the create sends it as `mcp_server_ids`.
  Until the list loads, the create sends no selection, which is what scuttle did before.
  The web UI also remembers a selection in the browser for the next new chat; scuttle starts each new chat from the defaults instead, since remembering it would add state for a choice the panel makes in two keys.
  While the chat is being created or loaded, `/mcp` and its toggles say to wait, so a selection never lands on the wrong chat.
- **What "connected" means for the `mcp` field.** It counts the servers the next message uses: the organization servers its selection turns on, with the required ones the server adds, plus the open chat's inline and workspace servers.
  It does not count connection health, because scuttle knows connect outcomes only from debug runs, only while debug logging is on, and only while `/mcp` is open.
  The field reads `/mcp: 3 on`, `/mcp: 0 on` when none are, and is hidden on a blank chat until the organization's list loads.
  It is optional and not in the defaults, takes no threshold, and gives way right after `queue`.
- **The wheel over overlays.** One wheel tick acts as one Up or Down key in the open table overlay, whichever overlay it is and wherever the pointer is, so it moves the selection where rows can be selected and scrolls the read-only panels.
  `/subagents` is the exception: the wheel moves its list only with the pointer over the list, and over the preview it scrolls the preview, so a trackpad flick never cycles preview streams.
  The wheel over the question menu moves it as Up and Down do.
  The help box, the effort slider, the slash menu, and an open one-line editor keep ignoring the wheel.
- **The archive confirmation.** Ctrl+A on a chat that is not archived opens a box over `/chats` titled `Archive “title”?` with "Archive", "Archive and delete workspace “dev”" (only when the chat has a workspace, in the error color), and "Cancel".
  It always starts on "Archive"; Enter on the delete choice arms it and says "Press D to delete workspace “dev” for good, Esc to cancel.", only D then deletes, and any move or other key disarms it.
  The workspace id is captured when the box opens, and the core refuses the delete if the chat's workspace changed since.
  A second Ctrl+A archives without deleting, so the old double press still archives.
  Esc or "Cancel" closes the box and leaves `/chats` open.
  Ctrl+A on an archived chat unarchives it at once, and a refusal the core already knows (a subagent, a running family) still answers at once without the box.
  Unlike the web UI, scuttle asks on every delete and never skips the question for a workspace the chat created, and it asks for Enter and then D instead of the typed workspace name, since the `/chats` list holds no workspace build history; the box names the workspace and warns that the delete cannot be undone.
  Ctrl+A in `/chats` is scuttle's only archive entry point; no slash command archives.

```rust
use std::path::{Path, PathBuf};

use serde::Deserialize;

use crate::config::{ConfigError, Existing, write_config};

/// What scuttle remembers between runs.
#[derive(Debug, Clone, Default, PartialEq, Eq, Deserialize)]
#[serde(default)]
pub struct LocalState {
    /// Whether the welcome screen already suggested a Nerd Font.
    pub nerd_font_tip_shown: bool,
}

/// `$XDG_STATE_HOME/scuttle/state.toml`, else `$HOME/.local/state/scuttle/state.toml`.
pub fn state_path(env: &dyn Fn(&str) -> Option<String>) -> Option<PathBuf> {
    let base = env("XDG_STATE_HOME").map(PathBuf::from).or_else(|| {
        env("HOME").map(|h| PathBuf::from(h).join(".local").join("state"))
    })?;
    Some(base.join("scuttle").join("state.toml"))
}

/// The state at `path`. A missing, unreadable, or damaged file reads as nothing remembered,
/// since forgetting a tip costs only one more showing.
pub fn load(path: &Path) -> LocalState {
    std::fs::read_to_string(path)
        .ok()
        .and_then(|text| toml::from_str(&text).ok())
        .unwrap_or_default()
}

/// Remembers that the Nerd Font tip was shown, keeping any other keys and comments the file
/// holds. A damaged file is replaced. The write is atomic and readable only by its owner.
pub fn record_nerd_font_tip(path: &Path) -> Result<(), ConfigError> {
    let mut doc: toml_edit::DocumentMut = std::fs::read_to_string(path)
        .ok()
        .and_then(|text| text.parse().ok())
        .unwrap_or_default();
    doc["nerd_font_tip_shown"] = toml_edit::value(true);
    write_config(path, &doc.to_string(), Existing::Replace)
}
```

```rust
    /// root cascades to its whole family on the server, so its children are marked the same

            .find(chat)
            .map(|c| c.children.iter().filter_map(|ch| ch.id).collect())

            self.chats
                .update_copies(child, |c| c.archived = Some(archived));

            .chats
            .find(chat)
            .cloned()
            .or_else(|| self.chat.as_deref().filter(|c| c.id == Some(chat)).cloned());
```

```rust
/// The widest the archive confirmation draws, so it reads as a box over `/chats`.
const ARCHIVE_WIDTH: u16 = 72;
const ARCHIVE_ROW: &str = "archive";
const DELETE_ROW: &str = "archive-delete";
const CANCEL_ROW: &str = "cancel";

/// The archive confirmation `/chats` draws over its rows: archive, archive and delete the
/// chat's workspace, or cancel. It starts on "Archive", and deleting takes Enter twice.
pub struct ArchivePrompt {
    pub chat: Uuid,
    pub title: String,
    /// The chat's workspace; `None` leaves out the choice that deletes it.
    pub workspace: Option<Uuid>,
    /// The workspace's name, when the workspace list holds it.
    pub workspace_name: Option<String>,
    pub table: TableState,
    /// Set by Enter on the delete choice, which then takes a second Enter; any move clears it.
    pub armed: bool,
}

impl ArchivePrompt {
    fn new(id: Uuid, chat: &types::CodersdkChat, app: &App) -> ArchivePrompt {
        let workspace = chat.workspace_id;
        ArchivePrompt {
            chat: id,
            title: chat
                .title
                .clone()
                .filter(|t| !t.trim().is_empty())
                .unwrap_or_else(|| "Untitled".into()),
            workspace,
            workspace_name: workspace
                .and_then(|ws| app.workspaces.iter().find(|w| w.id == ws))
                .map(|w| w.name.clone()),
            table: TableState::with_selected(RowKey::Action(ARCHIVE_ROW)),
            armed: false,
        }
    }

    /// How the confirmation names the workspace.
    fn workspace_phrase(&self) -> String {
        match &self.workspace_name {
            Some(name) => format!("workspace \u{201c}{name}\u{201d}"),
            None => "the chat's workspace".into(),
        }
    }
}

/// The archive confirmation's rows, with a warning under them while the delete is selected.
pub fn archive_view(prompt: &ArchivePrompt, theme: &Theme) -> TableView {
    let workspace = prompt.workspace_phrase();
    let mut rows = vec![Row::item(
        RowKey::Action(ARCHIVE_ROW),
        vec![Line::from("Archive")],
    )];
    if prompt.workspace.is_some() {
        rows.push(Row::item(
            RowKey::Action(DELETE_ROW),
            vec![Line::from(Span::styled(
                format!("Archive and delete {workspace}"),
                theme.error,
            ))],
        ));
    }
    rows.push(Row::item(
        RowKey::Action(CANCEL_ROW),
        vec![Line::from("Cancel")],
    ));
    let deleting = prompt.table.selected == Some(RowKey::Action(DELETE_ROW));
    let status = match (deleting, prompt.armed) {
        (true, true) => Some(format!("Press Enter again to delete {workspace}.")),
        (true, false) => Some(format!(
            "Deletes {workspace} and everything on it, for good."
        )),
        (false, _) => None,
    };
    TableView {
        title: format!("Archive \u{201c}{}\u{201d}?", prompt.title),
        widths: vec![Constraint::Fill(1)],
        rows,
        status,
        hint: Some("Up and Down choose, Enter confirms, Esc cancels".into()),
        filterable: false,
        ..Default::default()
    }
}

/// Draws `prompt` as a box in the middle of `area`, over the `/chats` rows.
pub fn render_archive_prompt(f: &mut Frame, area: Rect, prompt: &ArchivePrompt, theme: &Theme) {
    let view = archive_view(prompt, theme);
    let width = area.width.min(ARCHIVE_WIDTH);
    let height = table::height(&view, width).min(area.height);
    let rect = Rect {
        x: area.x + (area.width - width) / 2,
        y: area.y + (area.height - height) / 2,
        width,
        height,
    };
    table::render(f, rect, &view, &prompt.table, theme, None);
}
```

```rust
    /// A key while the archive confirmation shows, which holds the keyboard until a choice,
    /// Cancel, or Esc. Up and Down move between the choices, as the wheel does.
    fn archive_key(&mut self, key: KeyEvent, ctx: &ViewCtx) -> OverlayOutcome {
        let Some(prompt) = self.archive.as_mut() else {
            return OverlayOutcome::Stay;
        };
        let ctrl_a =
            key.code == KeyCode::Char('a') && key.modifiers.contains(KeyModifiers::CONTROL);
        let chosen = match key.code {
            // A second Ctrl+A archives, as the old double press did; it never deletes.
            _ if ctrl_a => Some(RowKey::Action(ARCHIVE_ROW)),
            KeyCode::Esc => None,
            KeyCode::Enter => {
                let view = archive_view(prompt, ctx.theme);
                prompt.table.selected_row(&view).map(|r| r.key.clone())
            }
            KeyCode::Up | KeyCode::Down | KeyCode::PageUp | KeyCode::PageDown => {
                let view = archive_view(prompt, ctx.theme);
                prompt.table.handle_key(key, &view);
                prompt.armed = false;
                return OverlayOutcome::Stay;
            }
            _ => return OverlayOutcome::Stay,
        };
        let chat = prompt.chat;
        match chosen {
            Some(RowKey::Action(DELETE_ROW)) if !prompt.armed => {
                prompt.armed = true;
                OverlayOutcome::Stay
            }
            Some(RowKey::Action(DELETE_ROW)) => {
                self.archive = None;
                OverlayOutcome::Send(Msg::ChatAction(ChatAction::ArchiveAndDeleteWorkspace(
                    chat,
                )))
            }
            Some(RowKey::Action(ARCHIVE_ROW)) => {
                self.archive = None;
                OverlayOutcome::Send(Msg::ChatAction(ChatAction::Archive(chat)))
            }
            // Cancel and Esc close the box and leave `/chats` open.
            _ => {
                self.archive = None;
                OverlayOutcome::Stay
            }
        }
    }
```

### Task 7: Label workspace start and stop rows the way the web UI does

**Spec:** Item 59 in `docs/feedback/2026-10-01-m2-daily-use.md`: a `start_workspace()` tool row shows empty parentheses, because the call has no required arguments.
The fix labels workspace start and stop rows like the web UI: "Starting workspace…" while running, then "Started <name>" or "Failed to start <name>" from the result.

**How the server and the web UI behave**, at `d1597a583b`:

- `start_workspace` takes only an optional `parameters` map ([`startWorkspaceArgs`](https://github.com/coder/coder/blob/d1597a583b/coderd/x/chatd/chattool/startworkspace.go#L37-L39)), and `stop_workspace` takes no arguments at all ([`stopWorkspaceArgs`](https://github.com/coder/coder/blob/d1597a583b/coderd/x/chatd/chattool/stopworkspace.go#L35)).
- A success names the workspace as `workspace_name`, with `build_id` or `no_build: true` ([`waitForAgentAndRespond`](https://github.com/coder/coder/blob/d1597a583b/coderd/x/chatd/chattool/startworkspace.go#L214-L269), [the stop results](https://github.com/coder/coder/blob/d1597a583b/coderd/x/chatd/chattool/stopworkspace.go#L128-L175)).
- A failed build comes back with `is_error` false and the failure in an `error` field, so its `build_id` survives ([`buildFailureToolResponse`](https://github.com/coder/coder/blob/d1597a583b/coderd/x/chatd/chattool/quotaerror.go#L163-L192), [`newBuildError`](https://github.com/coder/coder/blob/d1597a583b/coderd/x/chatd/chattool/chattool.go#L167-L182), [`responseErrorResult`](https://github.com/coder/coder/blob/d1597a583b/coderd/x/chatd/chattool/chattool.go#L68-L91)).
- A build refused for an exhausted quota adds `error_code: "INSUFFICIENT_QUOTA"` and a short `title` ([`quotaErrorResult`](https://github.com/coder/coder/blob/d1597a583b/coderd/x/chatd/chattool/quotaerror.go#L43-L57)).
- Other refusals, such as "chat has no workspace", are plain-text error results with `is_error` true and no `workspace_name`.
- The web UI draws both tools with one renderer ([`WorkspaceLifecycleRenderer`](https://github.com/coder/coder/blob/d1597a583b/site/src/pages/AgentsPage/components/ChatElements/tools/Tool.tsx#L1156-L1181), [`toolRenderers`](https://github.com/coder/coder/blob/d1597a583b/site/src/pages/AgentsPage/components/ChatElements/tools/Tool.tsx#L1196-L1197)).
  It counts the call as failed when `is_error` is set or the result has an `error` field.
- Its label reads "Starting workspace…" or "Stopping workspace…" while running, then a quota failure's `title` (else "Workspace quota reached"), else "Failed to start <name>" or "Failed to stop <name>" on error, else "Started <name>" or "Stopped <name>", with "workspace" when the result names none ([`WorkspaceLifecycleTool`](https://github.com/coder/coder/blob/d1597a583b/site/src/pages/AgentsPage/components/ChatElements/tools/WorkspaceLifecycleTool.tsx#L27-L39), [`getWorkspaceQuotaTitle`](https://github.com/coder/coder/blob/d1597a583b/site/src/pages/AgentsPage/components/ChatElements/tools/Tool.tsx#L187-L196)).
  It never shows the `parameters` in the header.

**Decisions:**

- The label follows the subagent heads' pattern in `transcript_view.rs`: a head struct beside `SubagentHead`, built where the call and its result meet, with the verb in the accent color and the raw call shown only when the row is expanded.
  It stays in `transcript_view.rs` rather than a module of its own like `subagent.rs`, since it needs no transcript-wide lookup such as `Titles`.
- The head leaves `parameters` out, as the web UI does, and the expanded row shows them in the raw call, such as `start_workspace({"parameters":{"region":"us-east"}})`.
  `args_summary` would show only the first value, such as `start_workspace(us-east)`, which reads as a workspace name and drops the parameter's name; the label's slot already holds the workspace name, and parameters are rare and set by the model, so they belong with the other raw details.
- The state marker also turns to `✗` when the result has an `error` field, as the web UI's row does, so a failed build never shows a green marker beside "Failed to start".
- The kind's icon slot and both icon modes stay as they are: `icons::tool_icon` already maps both tools to `Icon::Workspace`, and the head goes after the same `icons::lead` slot every tool row has.
- The `⎿` result line under the head, the footer's activity text, and `result_summary` are unchanged.

```rust
/// What a workspace lifecycle tool does to the chat's workspace.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
enum Lifecycle {
    Start,
    Stop,
}

impl Lifecycle {
    fn of(name: &str) -> Option<Lifecycle> {
        match name {
            "start_workspace" => Some(Lifecycle::Start),
            "stop_workspace" => Some(Lifecycle::Stop),
            _ => None,
        }
    }

    fn verb(self, phase: Phase) -> &'static str {
        match (self, phase) {
            (Lifecycle::Start, Phase::Running) => "Starting workspace…",
            (Lifecycle::Start, Phase::Done) => "Started",
            (Lifecycle::Start, Phase::Failed) => "Failed to start",
            (Lifecycle::Stop, Phase::Running) => "Stopping workspace…",
            (Lifecycle::Stop, Phase::Done) => "Stopped",
            (Lifecycle::Stop, Phase::Failed) => "Failed to stop",
        }
    }
}

/// The head of a `start_workspace` or `stop_workspace` call, worded as the web UI's
/// `WorkspaceLifecycleTool` words it.
struct LifecycleHead {
    /// The label in the accent color: the verb, or the title of a quota failure.
    verb: String,
    /// The workspace after the verb, else "workspace"; `None` while the call runs and after
    /// a quota title.
    object: Option<String>,
    /// The tool name and its arguments, shown when the call is expanded.
    raw: String,
    /// Whether the call failed, which a build failure reports only in the result's `error`
    /// field, with `is_error` false so the result keeps its `build_id`.
    failed: bool,
}

/// The `error_code` of a build refused because the workspace quota is full.
const INSUFFICIENT_QUOTA: &str = "INSUFFICIENT_QUOTA";

/// The head of `start_workspace` or `stop_workspace`, or `None` for any other tool. The
/// `parameters` a start may carry stay out of the label and show in the expanded call.
fn lifecycle_head(
    name: &str,
    args: Option<&serde_json::Value>,
    result: Option<&serde_json::Value>,
    done: bool,
    is_error: bool,
) -> Option<LifecycleHead> {
    let action = Lifecycle::of(name)?;
    let record = result_object(result);
    let field = |key: &str| {
        record
            .as_ref()?
            .get(key)?
            .as_str()
            .map(str::trim)
            .filter(|s| !s.is_empty())
            .map(|s| markdown::drawable(s).into_owned())
    };
    let failed = done && (is_error || field("error").is_some());
    let phase = match (done, failed) {
        (false, _) => Phase::Running,
        (true, true) => Phase::Failed,
        (true, false) => Phase::Done,
    };
    let quota = done && field("error_code").as_deref() == Some(INSUFFICIENT_QUOTA);
    let (verb, object) = if quota {
        let title = field("title").unwrap_or_else(|| "Workspace quota reached".to_owned());
        (title, None)
    } else if phase == Phase::Running {
        (action.verb(phase).to_owned(), None)
    } else {
        let workspace = field("workspace_name").unwrap_or_else(|| "workspace".to_owned());
        (action.verb(phase).to_owned(), Some(workspace))
    };
    let shown_args = args
        .filter(|a| args_summary(a).is_some())
        .map(|a| a.to_string())
        .unwrap_or_default();
    Some(LifecycleHead {
        verb,
        object,
        raw: format!("{name}({shown_args})"),
        failed,
    })
}

/// `result` as an object, parsing a result that arrived as a JSON string first.
fn result_object(
    result: Option<&serde_json::Value>,
) -> Option<serde_json::Map<String, serde_json::Value>> {
    match result? {
        serde_json::Value::Object(map) => Some(map.clone()),
        serde_json::Value::String(s) => match serde_json::from_str::<serde_json::Value>(s).ok()? {
            serde_json::Value::Object(map) => Some(map),
            _ => None,
        },
        _ => None,
    }
}
```
