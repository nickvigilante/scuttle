# M2 daily-use feedback, round 3

This file triages the feedback from the first day of using M2.
Each item has an answer or a proposed fix and a target.
"M2.5" means a polish round on top of M2, like M1.5 and M1.6.
Code references are to branch `m2`.

## Answers to direct questions

- **Customizing the status bar.**
  There is no setting today.
  The footer order is fixed in `crates/scuttle-tui/src/footer.rs` `footer_line`: model and effort, context usage, organization (only when you belong to more than one), plan mode, and connection status.
  The design schedules a configurable footer, `/statusline`, for M3.
- **The terminal tab title.**
  scuttle never sets it, so your terminal shows its default, the command path.
  Neither design plans it, and it is a small fix.
- **Changing settings.**
  The only settings file is `~/.config/scuttle/config.toml`, or `$XDG_CONFIG_HOME/scuttle/config.toml` if that variable is set.
  It accepts `mouse`, `busy_behavior` (`"queue"` or `"interrupt"`), `composer_max_lines`, `welcome.show`, `welcome.art_file`, `density.<tool>`, `organization`, and `efforts.<model-id>`.
  `/organization`, `/effort`, and the mouse toggle write to it for you.
  The full `/settings` menu is planned for M4.
- **The `/chats [query]` syntax.**
  Typing filters the list by title locally, with fuzzy matching.
  The last row, "Search all chats for …", sends `search:"<text>"` to the server.
  The server also accepts `title:`, `status:`, `archived:`, `has_unread:`, `pr_status:`, `pr:`, `pr_title:`, `repo:`, and `source:created_by_me|shared_with_me`, but scuttle does not pass those through yet.
- **`/org`.**
  It is already an alias of `/organization` (`crates/scuttle-core/src/commands.rs`), so no change is needed.
- **Non-blocking subagents.**
  Coder Agents launches subagents in the background, but the parent then calls `wait_agent`, which blocks the parent's turn for up to 5 minutes per call.
  A message you send meanwhile either waits in the queue or interrupts the whole turn, and nothing notifies the parent when a child finishes.
  No GitHub issue asks for this yet.
  The closest work is PR #29784, which names returning early from `wait_agent` as a follow-up, and PR #29715, which lets a child message its parent.
  The full research is in `docs/feedback/research-nonblocking-subagents.md`.
  It is a chatd feature, not something scuttle can do, so it was reported to the Coder Agents team.
